# Implementation Plan: Deploy Backend API Workflow

**Branch**: `003-deploy-backend-api` | **Date**: 2026-05-20 | **Spec**: `specs/003-deploy-backend-api/spec.md`  
**Input**: Feature specification from `specs/003-deploy-backend-api/spec.md`

## Summary

Add a dedicated GitHub Actions workflow at `.github/workflows/003-deploy-api.yml` that auto-triggers on pushes to `main`, reuses the existing environment/concurrency pattern from `001-deploy-infra.yml`, publishes `src/ai-genius-api` as a self-contained `linux-x64` build with .NET 10, zips the publish output, and deploys that package to Azure App Service via `azure/webapps-deploy@v3` using `vars.APP_SERVICE_NAME`.

## Technical Context

**Language/Version**: GitHub Actions YAML + .NET SDK 10 (`src/ai-genius-api/ai-genius-api.csproj` targets `net10.0`)  
**Primary Dependencies**: `actions/checkout@v4`, `actions/setup-dotnet@v4`, `azure/login@v1`, `azure/webapps-deploy@v3`, `dotnet publish`, zip packaging  
**Storage**: N/A (deployment pipeline only; no data model persistence)  
**Testing**: Workflow execution validation via GitHub Actions run outcomes and step-level failure visibility; deployment path validated by successful publish+zip+deploy run  
**Target Platform**: GitHub-hosted `ubuntu-latest` runner deploying to Azure Linux App Service (B1 plan)  
**Project Type**: CI/CD workflow for backend web service deployment  
**Performance Goals**: Reliable deployment completion within normal CI runtime (<10 minutes for publish+deploy in standard conditions)  
**Constraints**: Trigger only on `main`; preserve step order (`checkout` → `setup-dotnet` → `dotnet publish` → zip → `azure/webapps-deploy@v3`); use `vars.APP_SERVICE_NAME`; align environment/concurrency with `001-deploy-infra.yml`; fail fast on build/deploy errors  
**Scale/Scope**: Single workflow file plus supporting planning artifacts for one backend API deployment target
